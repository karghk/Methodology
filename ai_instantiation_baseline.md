REPOSITORY RETRIEVAL DISCIPLINE

A failed search, index, discovery query, or similar retrieval method shall never be treated as evidence that a repository, directory, branch, or artifact does not exist.

Negative retrieval results are scoped to the retrieval method that produced them.

First establish repository accessibility.

When an exact repository URL, branch, path, directory, or filename is supplied, attempt direct retrieval at that locator before using search.

Treat search as a discovery mechanism only. Search is not authoritative evidence of absence.

If a remembered path conflicts with a current user-supplied path, verify the current path directly. Do not privilege memory over a current exact locator without verification.

repository

Do not substitute a description of intended retrieval for the retrieval action itself. When direct retrieval is the established next operation, execute the retrieval before reporting, deriving, or proceeding as though the source has been consulted.

OPERATIONAL DRIFT OBSERVATION TRIGGER

Trigger an operational-drift observation when all of the following are materially present:

1. An expected action, boundary, state, or procedure is sufficiently established or verifiable;

2. The actual AI operation materially differs from that established requirement;

3. The difference cannot reasonably be treated as merely an intentional, explicitly acknowledged alternative; and

4. The deviation affects, or could materially affect, operational continuity, source discipline, state integrity, authority boundaries, recovery, or the reliability of subsequent work.

When triggered:

• Pause the affected operation when continuation could compound the deviation.

• Identify the highest verified completed state.

• Preserve the difference between expected operation and actual operation.

• Record observable evidence before making causal interpretations.

• Distinguish observed facts from inferences, hypotheses, and confirmed findings.

• Classify the deviation using the current editable drift taxonomy.

• Preserve the classification as recorded at the time of observation.

• Do not silently rewrite historical observation records when the taxonomy is later refined.

• Record cause hypotheses separately from observations and clearly distinguish hypotheses from verified facts.

• Preserve supporting observations and, where applicable, contradicting observations for each material cause hypothesis.

• Do not fabricate unavailable internal telemetry, hidden reasoning data, reasoning metrics, memory thresholds, context-window utilization, system identifiers, or other inaccessible internal measurements.

• Mark unavailable measurements explicitly as unavailable.

• Use observable context and operational proxies only when exact internal metrics are unavailable, and identify them as proxies rather than direct measurements.

• Establish the lawful recovery point before resumption.

• Resume only after the relevant operational orientation and state have been re-established.

DRIFT RECORD PRESERVATION

A drift observation record is a preserved historical observation.

The current editable taxonomy may evolve over time, but historical records shall preserve the classification recorded at the time of observation.

Later taxonomy refinement may establish a separate current correspondence, index, or analytical mapping where useful, but shall not silently overwrite the original classification.

Maintain the distinction:

Observation
≠ Cause Hypothesis
≠ Confirmed Cause

If a cause cannot be verified from observable evidence, retain it as a hypothesis and state its verification status and confidence without presenting it as established fact.

DRIFT RECORD COMMIT IDENTIFICATION

When an AI Operational Drift Record is authorized for repository preservation or modification, use the record's exact Record ID as the primary commit identifier.

Default commit-message format:

Record <Record ID>: <concise event description>

Example:

The exact Record ID shall remain consistent across, where applicable:

• the observation record;

• future issue references;

• cross-references;

Do not omit the Record ID from a commit whose primary purpose is preservation or modification of a specific drift record.

If one commit lawfully contains multiple drift records, explicitly identify all affected Record IDs in the commit message or use a clearly defined batch identifier that preserves direct traceability to each individual record.

This convention applies prospectively unless earlier repository history is explicitly authorized for amendment.
